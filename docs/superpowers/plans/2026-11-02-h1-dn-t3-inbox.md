# Implementation plan — DN-T3 Inbox surface (epic #39 / SIL-205)

Branch: `feat/205-dn-t3-inbox` (base: `feat/204-dn-t2-quick-capture`).
Spec: `docs/superpowers/specs/2026-11-02-h1-daily-notes-quick-capture-inbox-design.md` §DN-T3.
Design dependency: DN-T2 capture bullets (`HH:MM … #inbox`) and the persister fix that indexes
editor `XmlFragment` text into `pages.searchable_text`.

## Counting rule (locked for this slice)

A capture is **pending** while its bullet still carries `#inbox`.

- `fetchInboxItems(workspaceId)` reads the workspace's daily pages for the **last 14 local days**
  (today inclusive), ordered newest day first, and parses `searchable_text` line by line.
- A line counts when it matches `(?:^|\s)#inbox\b` (case-insensitive), with an optional markdown
  bullet prefix stripped. Lines without `#inbox` are processed and excluded.
- `o` (link) removes `#inbox` from the bullet, so it stops counting. `Del` deletes the bullet.
  `t` (tag) keeps `#inbox`, so it stays pending. No schema change, no new write path.

The persister now joins block-level nodes (including each `listItem`) with newlines before
indexing, otherwise two captures in one bullet list collapse into one line and under-count.

## InboxCard (dashboard)

`components/inbox-card.tsx`: count + top five pending items, loading/empty/error states, and an
"Open Inbox" action that resolves today's daily page with `ensureDailyPage` and routes to
`/page/<id>?section=inbox`. Refetches on window focus/visibility (the graph index is updated by
the hub's 2s idle save). Every control is a labelled native button; the list is announced via
`aria-live`.

## Daily-page triage (focused rows)

`lib/inbox-triage.ts` (pure ProseMirror helpers) + `lib/inbox-triage-extension.ts`:

- A row is focusable when the selection sits inside a `listItem` under an `Inbox` heading
  (level ≤ 2) whose text carries `#inbox`.
- `Delete` removes the whole row; `o` opens the page picker; `t` opens the tag input.
  Keys never fire outside a focused inbox row, while composing, or with modifiers held.
- `o`: append `[[<daily page title>]] <capture text>` to the target page's **Related actions**
  section over the target page's CRDT channel (same append path as captures), then replace the
  row text with `<capture text> [[<target title>]]` and drop `#inbox`.
- `t`: append `#tag` to the row and keep `#inbox`.
- `components/inbox-triage-dialog.tsx`: labelled Radix dialog; page search reuses
  `services/search.ts searchPages`; tag input validates the existing `#tag` grammar.

`components/editor-workspace.tsx` mounts the extension (editors only), owns the dialog, and
scrolls to the Inbox heading when the URL carries `?section=inbox`.

## Tests

1. `tests/unit/inbox.test.ts` — window (14 local days), line parsing (processed excluded),
   count + ordering + limit, non-daily pages ignored, query error propagation.
2. `tests/unit/inbox-card.test.tsx` — count/top five, empty, loading, error + retry, open Inbox
   creates today's page and routes with `?section=inbox`.
3. `tests/unit/inbox-triage.test.tsx` — real Tiptap editor: keys fire only in a focused inbox row,
   `Delete` removes one row, `o`/`t` invoke callbacks, tag/link text helpers, modifiers ignored.
4. `tests/unit/sync-persister.test.ts` — regression: two captures in one bullet list are indexed
   on separate lines.

## Out of scope

- Capture channels other than the palette (email/Telegram), offline queue (spec non-goals).
- Reworking the Inbox section into a separate view; the editor body remains the source of truth.
