---
title: BYOK Setup
description: Bring your own cloud provider key and keep it encrypted on your device.
---

**BYOK** (bring your own key) connects a cloud AI provider with a key you control. Cloud requests are
relayed through Lekhan's API using *your* key: the key is stored encrypted, usage is never metered, and
prompts are not kept as AI logs. Local providers (Ollama, LM Studio) are the exception — those requests
go straight from your browser to `localhost`.

## Supported providers

- Anthropic
- OpenAI
- Google Gemini
- DeepSeek
- Qwen
- Z.AI
- Groq
- OpenRouter
- Sarvam
- Any OpenAI-compatible endpoint (**Custom** base URL)

You can configure more than one provider and switch between them per request.

## Steps

1. Create an API key in your provider's dashboard. Give it the narrowest scope that works for you.
2. Open **Settings → AI** and choose the provider.
3. Paste the key. Lekhan encrypts it with AES-256-GCM in your browser before it is stored; the
   ciphertext is kept with your profile, and only the decryption key stays on your machine.
4. Pick a model and send a test prompt.

## What Lekhan stores

- The **encrypted** key (AES-256-GCM ciphertext) with your profile.
- Your provider and model selection.
- Nothing else: prompts and responses are not persisted as AI logs, and usage is never metered.

<Callout type="info" title="Encrypted before storage">
The decryption material stays on the device where you added the key. If you clear site data or use
another browser, you will need to paste the key again. Lekhan cannot recover a key for you.
</Callout>

## Security checklist

- Use a dedicated key for Lekhan rather than a personal master key.
- Set a spend limit at the provider if it offers one.
- Rotate the key in the provider dashboard, then replace it in **Settings → AI**.
- Remove a key in Lekhan when you stop using a provider; removal does not affect your pages.

## Custom endpoints

For a provider that speaks the OpenAI API, choose **Custom** and enter the base URL (for example an
internal gateway, including its `/v1` prefix). The same encryption and relay rules apply.
