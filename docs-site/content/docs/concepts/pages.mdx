A **page** is the universal node in Lekhan. It holds content and properties, can nest under another
page, and can be linked from anywhere in the workspace.

<Callout type="info" title="Page, not document">
Older versions of Lekhan used a flat "document" model. Current pages are graph nodes — nested,
linkable, taggable, and searchable.
</Callout>

## What a page can hold

- **Rich content**: headings, lists, tables, code blocks, images, callouts, and embeds.
- **Page properties**: structured metadata attached to the page. Imported frontmatter becomes page
  properties on the way in.
- **Links**: `[[wikilinks]]` to other pages, which create the graph edges.
- **Tags**: inline `#tags` indexed for filtering.
- **Versions**: point-in-time snapshots retained according to your plan's history window.

## Nesting and structure

Pages can nest to mirror how you think — projects inside areas, meeting notes inside a client page,
and so on. Nesting is organizational; **links** are what connect ideas across folders.

## Markdown round-trip

Lekhan's editor converts content to markdown and back. The **round-trip** guarantee is the guardrail:
a page should survive editor → markdown → editor without losing structure. This is also why imports
and exports are trustworthy: your content is never trapped in a proprietary format.

## Properties on import

Frontmatter in a markdown file is extracted into page properties. Import and paste both use the same
path, so metadata comes along even when the body is empty (for example, a frontmatter-only note).
